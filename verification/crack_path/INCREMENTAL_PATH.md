# General incremental crack-path driver

## Status

This branch converts the validated Stage III-C/D sequence into a reusable
incremental algorithm.

The scientific convention is fixed:

1. The first finite segment is initialized at

       theta_1 = 0 deg

   along the frozen material-side normal at the Stage-I initiation point.

2. The accepted P1 physical SIFs are

       KI(P1)  = 0.366479612185 MPa sqrt(m)
       KII(P1) = 4.19826648316e-6 MPa sqrt(m)

   and determine theta_2 by the production MTS routine.

3. For every later current tip P_k,

       fixed path P0 -> ... -> P_k
         -> qualify the complete polyline
         -> one physical LEFM solve
         -> KI(P_k), KII(P_k)
         -> Delta theta_{k+1} by MTS
         -> theta_{k+1} = theta_k + Delta theta_{k+1}
         -> append exactly one 4-mm segment.

No angle sweep is part of the production path.

## Production components

### qualify_incremental_crack_candidate.m

Input:

    pathGlobal = [P0; P1; ...; Pk]

with at least two finite crack segments.

The routine generalizes the accepted Stage III-C qualification. It keeps:

- the true appended-hole polyline carrier;
- exact upper/lower face separation at every interior path vertex;
- the explicit retained crack polyline in the exterior;
- the qualified 4-mm-scaled paired current-tip core;
- hTip/Delta-a = 0.00675308135;
- rInner/Delta-a = 0.10;
- rOuter/Delta-a = 0.65;
- rCore/Delta-a = 0.75;
- transition/Delta-a = 1;
- far cap/Delta-a = 0.625;
- last-segment COD and EDI frames;
- exact native near-tip sampling 38/55/44/34;
- prescribed pure-I, pure-II, and tiny-mixed Williams replay.

It performs no physical solve.

### solve_incremental_crack_tip.m

Input is one qualified candidate.

The complete path is fixed geometry. The routine performs exactly one
checkpointed physical LEFM solve at the current tip and then reports

    KI_k
    KII_k
    KII_k/KI_k
    Delta theta_{k+1}
    theta_{k+1}.

The solver architecture is unchanged from accepted Stage III-B/D:

- free-DOF SPD formulation;
- unclamped symmetric stiffness assembly;
- frozen minimal anchors;
- exact unit remote-y traction;
- symamd;
- parameter-free symmetric Gauss-Seidel preconditioner;
- PCG tolerance 1e-10;
- maximum 5000 iterations;
- true residual gate 5e-10;
- exact constraints;
- no direct backslash solve;
- checkpoint before any COD/EDI/MTS postprocessing.

The COD extractor is always native_COD_polyline_audit.m.
The interaction EDI already uses the last segment.

No new crack segment is generated by this routine.

### run_incremental_crack_path.m

This is the production orchestrator.

It:

- initializes P0 -> P1 with theta_1=0;
- obtains theta_2 from the accepted P1 SIFs;
- builds P2;
- loops from k=2 to MaxSegments;
- qualifies the entire current polyline;
- solves one current-tip physical state;
- applies MTS;
- appends one new 4-mm segment;
- stores per-step candidates, physical checkpoints, and compact results;
- stops before the proposed next-tip paired core would meet a physical
  boundary;
- saves incremental_path_result.mat.

The default is safe:

    AllowPhysicalSolves = false

and the default

    MaxSegments = 5

is intentionally a short first production run rather than an unrestricted
long calculation.

## Regression lock

The generic driver is not allowed to continue beyond P2 unless it reproduces
the accepted Stage III-D physical state.

Anchors:

    theta_2 = -0.00131272214162 deg

    KI(P2)  = 0.437864119925 MPa sqrt(m)
    KII(P2) = 4.10524020214e-05 MPa sqrt(m)

    Delta theta_3 = -0.0107436495453 deg
    theta_3       = -0.0120563716869 deg

The production regression tolerances are intentionally much tighter than the
scientific discretization uncertainty. They are intended to detect code-path
changes, not estimate physical error.

## First test: three segments

Run:

    addpath(genpath(pwd));

    Path3 = main_incremental_path_regression( ...
        'FrozenState', R0, ...
        'AllowSolve', true);

This first:

1. rebuilds the generic two-segment candidate;
2. performs the generic P2 physical solve;
3. requires exact regression to accepted Stage III-D within the coded
   tolerances;
4. appends the predicted third 4-mm segment;
5. qualifies and physically solves the new P3 state;
6. predicts theta_4.

This is the first test that exercises a genuinely new point beyond the
previous staged calculations.

## Short production test: five segments

After the three-segment regression passes:

    Path5 = run_incremental_crack_path( ...
        'FrozenState', R0, ...
        'MaxSegments', 5, ...
        'AllowPhysicalSolves', true, ...
        'RunSynthetic', true);

The driver reuses matching candidate files and physical checkpoints from
earlier steps.

## Longer path

Only after the short regression is accepted, increase MaxSegments, for
example:

    Path = run_incremental_crack_path( ...
        'FrozenState', R0, ...
        'MaxSegments', 30, ...
        'AllowPhysicalSolves', true, ...
        'RunSynthetic', true);

The current implementation stops before the proposed next-tip 3-mm paired
core would intersect a plate or circular-hole boundary.

This is a numerical termination rule for the qualified sharp-tip machinery;
it is not a separate fracture criterion.

## Output directory

By default:

    verification/crack_path/incremental_run/

Per-step files are

    step_002_candidate.mat
    step_002_qualification_small.mat
    step_002_physical_solved.mat
    step_002_physical_small.mat
    ...

and the accumulated result is

    incremental_path_result.mat

A compact path_run_state.mat is also updated after every accepted appended
segment.

## Performance

This implementation deliberately prioritizes scientific equivalence and
regression safety over speed.

Likely optimization targets after the three- and five-segment tests pass are:

- repeated carrier/exterior topology discovery;
- repeated T3-to-T6 conversion;
- repeated sparse stiffness assembly;
- preconditioner construction;
- candidate reuse/resume behavior;
- synthetic replay frequency.

No solver tolerance, EDI radius, mesh scale, MTS convention, or qualification
gate should be changed merely to improve runtime.
